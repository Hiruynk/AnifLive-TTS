# AnifLive-TTS v1.3 Reference-Directed Expression Control

## Scope

The AnifLive-TTS v1.3 candidate explores a feature release based on immutable v1.2 commit
`e8386758ac3629483c8ca761f42c3b96f58144e0`. The v1.3 latency architecture
experiments remain closed historical research. R3, R4, and R5 results are not
deleted, rewritten, or used as the production runtime for this work.

No rejected MTP, Mamba, SemanticPiece, or FastStart path is reopened.

## Product Contract

Clients request a validated symbolic expression profile and optional discrete
intensity. They cannot submit a local path, URL, uploaded recording, reference
transcript, or any other reference override.

The server resolves the symbolic request to an administrator-curated reference
inside the active model package. All neural reference preparation is completed
at startup and remains GPU-resident during serving.

The first release does not claim a learned continuous emotion latent. Intensity
selects the closest curated reference variant. Capabilities therefore report
controlled profiles as supported and continuous vectors as unsupported.

## Architecture Boundary

The production neural architecture remains v1.2:

- GPT-SoVITS V2ProPlus;
- TensorRT 11 FP16;
- nine TensorRT neural stages;
- the Transformer semantic decoder;
- the existing SoVITS and SoVITS streaming engines;
- the established 9+8 first-preview behavior;
- no PyTorch neural production fallback.

Latency is a regression gate rather than an optimization objective.

## Research Order

1. Refactor the one fixed reference into a one-entry `PreparedReferenceBank`
   with exact v1.2 behavior.
2. Add optional schema-1 expression metadata and package-safe administration
   tooling.
3. Prepare the complete reference bank at model activation.
4. Add global symbolic expression routing and discovery.
5. Compare full switching, identity lock, semantic style, acoustic style, and
   speaker-vector-only control.
6. Add explicit segmented requests and punctuation-aware boundary kinds.
7. Establish natural-pause hard switching, then evaluate context, acoustic
   state carry, crossfade, and same-semantic reference bridge candidates.
8. Promote only the simplest candidate that passes content, identity,
   expression, streaming, latency, and blinded-listening gates.

Roxy is the only exploration model. Miku and the formal five-language release
matrix begin only after Roxy passes the feature gate.

## Experimental Findings

Roxy passed the feature gate before Miku validation began. The selected
runtime uses the same package-driven `semantic-style` conditioning policy for
both models, with natural hard transitions and tiered progressive refill. No
runtime branch checks a character or model name.

| Model | Controlled-expression rows | Controlled streams | Neutral controls |
|---|---:|---:|---|
| Roxy V2ProPlus | 16/16 passed | 48/48 without underrun | 2/2 passed |
| Miku V2ProPlus | 16/16 passed | 48/48 without underrun | 2/2 passed |

In the final Japanese full-expression matrix, Roxy's minimum stream-to-complete
log-mel cosine was `0.994325`, and its minimum speaker cosine was `0.987721`.
Miku's corresponding minima were `0.999454` and `0.989519`. Both models stayed
within a `0.31%` duration difference and produced no contractual playback
underruns.

The final five-language matrix separately tested long and short neutral plus
`languid` cases in `zh`, `yue`, `en`, `ja`, and `ko`. Miku passed all 20 rows
with controlled minima of `0.999660` log-mel and `0.988638` speaker cosine.
Roxy passed all 20 rows with controlled minima of `0.998827` and `0.993495`.
Both models produced zero contractual playback underruns.

Neutral complete WAV, streaming PCM, complete semantics, and streaming
semantics are exactly equal to the immutable v1.2 baseline for both models in
all five languages. The earlier playback discrepancy was traced to a
zero-prebuffer stress simulation that did not model the published playback
contract. Zero-prebuffer results remain diagnostic; API-recommended prebuffer
playback is the release gate.

The following candidates were evaluated and rejected because they either did
not correct that case or caused a larger quality or latency regression:

- alternate progressive-refill windows and token counts;
- shorter first-preview publication thresholds;
- identity-lock conditioning;
- partial preview through the complete-audio engine;
- two reference-onset normalization policies.

The accepted Roxy policy was not weakened to make the Miku result pass. The
final policy remains generic and package-driven; there is no runtime branch on
character or model name.

## Release Qualification Evidence

Real Linux Docker acceptance used TensorRT 11 on the RTX 5070 Ti with network
access disabled. Both model packages passed five-language complete and stream
requests, controlled-expression streaming, legacy flat and OpenAI-compatible
adapters, invalid-input handling, transactional model switching, and explicit
stream cancellation recovery. The active process loaded one model at a time
and reported no PyTorch neural fallback.

A same-round v1.2/v1.3 neutral comparison retained exact outputs. Its bounded
direct-service timing diagnostic reported Miku first-packet P50 changing from
`57.258 ms` to `53.068 ms` and Roxy from `59.630 ms` to `59.133 ms`; complete
RTF also improved for both. This diagnostic is not a canonical HTTP benchmark
and is not used to update public performance claims.

The canonical release benchmark uses Roxy only. Across 10 session-level
statistics, keep-alive audible TTFA P50 was `74.578 ms` and complete-WAV RTF
P50 was `0.087680`. Every formal request reported TensorRT 11 and no PyTorch
neural fallback.

## WebUI Candidate

The v1.3 candidate includes a local WebUI with the existing dark wine and lilac
visual language. It provides five speech languages, local model switching,
streaming PCM playback, the existing eight latency/playback metrics, and a
natural-language expression request field. Free-form text is resolved only to
symbolic profiles supplied by the active model package; paths, URLs, uploaded
references, and arbitrary transcripts are never forwarded to the runtime.

The WebUI is launched with `run_webui.bat` after the local API is ready. It does
not install packages, pull images, build engines, or start a second neural
runtime. Explicit stream cancellation prevents an abandoned browser request
from leaving the single TensorRT execution context busy.

Objective WebUI integration checks used the real Linux Docker TensorRT runtime
for both Roxy and Miku. The proxy added less than `0.9 ms` median overhead for
each model in the bounded integration run. These figures are integration
diagnostics, not a replacement for the canonical release benchmark.

## Release Decision

**PASSED.** The software, API, WebUI, TensorRT enqueue, cancellation, neutral
parity, Japanese full-expression matrix, post-policy five-language matrix, and
independent blind-listening gate pass. The six blind pairs produced five
no-difference decisions, one preference for the Roxy complete output, and no
reported artifact. v1.3 retains the v1.2 neural architecture and promotes the
generic package-driven expression contract.
